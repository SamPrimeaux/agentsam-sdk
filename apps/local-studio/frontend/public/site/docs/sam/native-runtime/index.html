Native runtime

Go where machine work benefits from Go.

AgentSam's native Go runtime handles fast machine-level execution while the TypeScript/protocol layer remains the contract authority.

Current production shape
Cloudflare Worker edge adapter → native Linux Go Container. The same runtime core is intended to power the local agentsamd daemon.

What it does today

  • Reports health, source identity, runtime information, and capabilities.
  • Computes deterministic SHA-256 hashes.
  • Runs deterministic static inspection.
  • Returns AgentSam ErrorEnvelope-compatible request failures.

Different ownership modes, one shared contract

Local native development

Maintainers can run the Go process directly. AgentSam verifies the built binary by booting it, probing the contract, matching source identity, and requiring clean shutdown.

Cloudflare development

Wrangler runs the Worker edge adapter with the GO_RUNTIME Container binding. This mode is for development, not final production proof.

Hosted service and advanced self-host

Normal AgentSam users consume the official hosted service where appropriate; they do not deploy it just to use AgentSam. Advanced self-hosters install the separate Go service artifact and deploy only to an explicitly selected Cloudflare account. IAM product registration is a separate guarded maintainer path.

agentsam go --cloudflare agentsam-go-worker --dry-run --account <account-id>

What counts as shipped

A source tree, Dockerfile, or deployment adapter is not deployment proof. A production receipt is accepted only after the externally reachable service reports healthy and both edge and native health identify the intended source identity.

Evidence captured

  • Git or npm package source identity plus deterministic source digest
  • native binary SHA-256 digest
  • linux/amd64 nonroot container verification
  • explicit Cloudflare account identity
  • Cloudflare deployment ID and Worker version ID
  • deployed URL and timestamped endpoint probes
  • local AgentSam registry for self-host deployments
  • agentsam_products / asset_relationships only for guarded IAM official releases

What comes next

The shared native core graduates next into workspace filesystem execution, file watching, Merkle updates, health/capability state, cancellable jobs, and PTY coordination. agentsamd reuses that core as the user-machine runtime; the hosted Go Worker remains a separate service with a different ownership boundary.
