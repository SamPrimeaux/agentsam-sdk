Plugin contract checklist

  • Discovery and stable identity
  • Frontend/backend/native entry points
  • Capability grants rather than entire host internals
  • Activation/disposal lifecycle
  • Process/WASM/worker isolation
  • Host API and protocol compatibility
  • Scoped persistence and observability
Dynamic import is not a plugin architecture. The architecture is the constrained, versioned contract around the imported code.
Authority

Local vs cloud

“Local” and “cloud” describe placement. Authority describes who is allowed to decide. A robust design can have cloud-owned identity, locally owned live execution, and separately durable operation receipts.

PlaneOwns
Controlidentity, policy, enrollment, configuration
Datalatency-sensitive payload and execution
Observabilitylogs, traces, metrics, receipts
Build/releasetrusted artifacts, signing, SBOM, publishing
cloud policy ── authorizes ──▶ local runtime
                                  │
                            live session/data
                                  │
                         durable receipt/event
Protocols

RPC, gRPC, generated contracts

A process boundary turns ordinary calls into distributed-systems calls: they can time out, be retried, arrive twice, arrive late, or fail after the remote side committed work.

foo.proto ── protoc ──▶ foo.pb.go
                     ├▶ foo_grpc.pb.go
                     ├▶ Python/TS/Rust bindings
                     └▶ descriptors

.proto, .capnp, GraphQL schemas, OpenAPI documents, JSON-RPC methods and WIT interfaces are all ways of turning assumptions into inspectable contracts.

State

Persistence and migrations

A database is not one thing. Relational truth, local working state, immutable artifacts, event history, caches and search indexes need different guarantees.

001_create.sql
002_add_nullable_owner.sql
003_backfill_owner.sql
004_enforce_owner.sql

The staged sequence above is architecture: it allows mixed-version software and existing data to survive change.

Creative systems

CAD / 3D / scene representations

Learn representation before format. STL is usually triangle mesh; STEP commonly carries precise CAD geometry; OpenSCAD is source code that produces geometry; USD is scene description/composition; IFC carries BIM semantics.

RepresentationPreserves
Meshrenderable surface
B-repprecise topology + surfaces
Parametricfeature history + constraints
Scene graphhierarchy, transforms, references, materials, time
BIMbuilding semantics + geometry + relationships

“4D” usually means 3D plus time: animation, simulation, or BIM scheduling—not one magic fourth-dimensional file format.

  • gRPC — Cross-language RPC implementation; native build systems.
  • gRPC Go — Go RPC stack and protobuf/gRPC code generation.

Engineering practice

What mature teams optimize

  • Explicit ownership and small blast radius
  • Compatibility during rolling change
  • Structured observability and correlation IDs
  • Data migration discipline
  • Cancellation, deadlines, retries and idempotency
  • Least-privilege capabilities and trust boundaries
  • Tests aligned with architectural boundaries
  • Reproducible builds and generated artifacts
  • Deletion of old shims and duplicate authority
identity ≠ permission ≠ capability ≠ possession of every secret
