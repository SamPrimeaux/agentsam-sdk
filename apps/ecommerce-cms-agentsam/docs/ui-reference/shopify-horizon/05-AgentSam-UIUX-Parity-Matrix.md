**Inference, not established diagnosis:** `CmsThemeSettings.read()` returns null when no site-owned `brand` section is available; the live renderer shows its loading branch when read returns null/undefined. That is a plausible explanation for the observed loading state. No database query, request tracing or mutation was done to confirm the exact cause.

**Do not promote review code by accident:** `theme-settings-panel.js` explicitly labels itself an isolated frontend review with no CMS writes. Current HTML loads `theme-settings-live.js` and `resolve-theme-settings.js`, not that isolated panel. The React `cms-editor/.../CmsEditor.tsx` is another existing implementation surface with adapter-owned state; it was inspected only to identify overlap and was not established as the live `/admin/theme-editor` route. No replacement or deletion recommendation is justified without a route/import ownership decision.
