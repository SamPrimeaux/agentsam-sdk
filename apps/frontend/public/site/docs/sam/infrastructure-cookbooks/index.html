Infrastructure cookbooks

Practical tests for proving that AgentSam's machine layer can understand large codebases, detect change, predict blast radius, choose the right evidence, recover from failures, and verify heavy infrastructure work without brute-force model exploration.

Test outcomes, not commands

Merkle, AST, GOAP, retrieval, terminal lanes, security scans, and verification scripts are implementation details. The benchmark is whether SAM reduces unnecessary exploration and produces smaller, safer, evidence-backed work.

How to test SAM

A powerful infrastructure primitive is only useful if it removes cognitive work from the operator. Every cookbook asks: did SAM find the smallest correct surface, act deliberately, and prove the result?

human goal
   │
   ▼
SAM perception
   ├─ repository state
   ├─ Merkle delta
   ├─ AST / dependency graph
   ├─ indexed retrieval
   └─ runtime health
   │
   ▼
plan / execute / verify
   │
   ▼
receipt
   ├─ predicted impact
   ├─ actual impact
   ├─ tests
   ├─ evidence
   └─ remaining uncertainty
Rule: do not judge success by whether a command completed. Judge success by whether SAM changed the intended state and preserved unrelated authority.
Cookbook 01

Establish a SAM baseline

01
Repository perception before editsCreate a reproducible view of the repo before a large task begins.
runnable now
shell
git status --short
git rev-parse HEAD

agentsam inspect

agentsam merkle snapshot . \
  --semantic \
  --out /tmp/sam-before.json

agentsam index plan --cwd . --json
agentsam index run --cwd . --json

Then query only the surface relevant to the task:

shell
agentsam search "terminal enrollment authentication" \
  --cwd . --top-k 8 --token-budget 4000
Good result: SAM identifies the authority files without requiring a model to crawl the entire repository.
Cookbook 02

Prove Merkle saves work

02
Incremental intelligence testMeasure what can be invalidated versus reused after a bounded change.
runnable now
before
agentsam merkle snapshot . --semantic --out /tmp/sam-before.json

Make one bounded change, then capture the new state:

after
agentsam merkle snapshot . --semantic --out /tmp/sam-after.json
agentsam merkle diff /tmp/sam-before.json /tmp/sam-after.json --json
Good result: SAM can say which subtrees changed, which analyses are invalid, and which previous work can be reused.
Cookbook 03

AST blast-radius test

03
Predict impact before editingCompare structural predictions to the actual changed surface.
runnable now
  1. Pick a cross-cutting symbol or contract.
  2. Index the codebase.
  3. Ask SAM to identify likely callers, schema dependencies, tests, and runtime boundaries.
  4. Make the change.
  5. Compare predicted impact to the actual Merkle delta and test failures.
shell
agentsam index run --cwd . --json
agentsam search "terminal session account ownership verification" --cwd . --top-k 12
Metric: blast-radius recall = affected components found before editing ÷ affected components discovered overall.

Retrieval routing bake-off

runnable now
structural
agentsam index run --cwd .
agentsam search "where openSideTab handles terminal" --cwd . --top-k 8
semantic
agentsam index run --cwd . --embed --json
agentsam search "code responsible for deciding where terminal work should execute" \
  --cwd . --semantic --top-k 8 --token-budget 4000

Cookbook 05

GOAP planning proof

05
Deterministic plan behaviorUse the currently available brand planner as a live GOAP laboratory.
runnable now
shell
agentsam brand scan --json
agentsam brand resolve --json
agentsam brand plan --goap --json

Run from an isolated worktree, introduce one controlled inconsistency, and record initial state, candidate actions, selected plan, cost, preconditions, and expected effects.

Good result: identical state produces the same plan; meaningfully different state produces a meaningfully different plan.
Cookbook 06

Package-release torture test

06
Break one thing at a timeForce SAM to isolate the smallest release-readiness failure.
repo scripts
The public CLI does not currently expose a finished agentsam package command. Use repository verification scripts for this drill.
verification
npm run verify:package
npm run pack:check
npm run test:workspaces
npm run verify:boundaries
npm run verify:release
Good result: SAM reports the exact failing gate and avoids inspecting unrelated subsystems.
Cookbook 07

Security + trust-boundary drill

07
More than dependency scanningTest AST + Merkle evidence around client/server and secret-handling boundaries.
runnable now
shell
agentsam security scan --path . --offline --json
agentsam security scan --path . --json
agentsam security repair --path . --json
Good result: SAM identifies a trust-boundary violation from structural evidence before it becomes a production bug.

Massive infrastructure stress test

Use this against a real cross-cutting infrastructure task: identity migration, terminal runtime changes, release systems, or schema authority moves.

before edit → inspect · merkle · index · retrieval · predicted blast radius
implementation → smallest affected surface · preserve unrelated WIP
verification → focused tests · boundary/security · second Merkle · compare
SAM work receipt

Reusable coding-agent instruction

Paste this into a capable coding agent when you want it to use AgentSam's machine tooling strategically.

operator prompt
Use AgentSam's machine tooling before broad model exploration.

Goal:
<REAL INFRA TASK>

Before editing:
1. Record git HEAD and working-tree state.
2. Run `agentsam inspect`.
3. Create a semantic Merkle snapshot outside the repository.
4. Run `agentsam index plan --cwd . --json`.
5. Run/update the structural index if necessary.
6. Retrieve the smallest relevant code surface using `agentsam search`.
7. Report current authority, predicted blast radius, relevant files,
   expected tests/verifiers, and evidence gaps.
8. Do not perform a broad repository crawl unless existing evidence is
   insufficient. Explain why more exploration is needed.

During implementation:
- Prefer existing contracts and repository authority.
- Do not silently create parallel abstractions.
- Re-query structural evidence when crossing a predicted boundary.
- Preserve unrelated working-tree changes.

After implementation:
1. Run the smallest affected tests first.
2. Run applicable package/boundary/security verification.
3. Create a second semantic Merkle snapshot and diff before vs after.
4. Compare actual changes against predicted blast radius.
5. Return a SAM work receipt (goal, baseline commit, evidence,
   predicted vs actual surface, tests, verification, unexpected
   findings, remaining uncertainty, recommended next action).

Do not report success merely because code was written.
Success requires evidence that the intended state changed and unrelated
authority remained intact.

SAM benchmark scorecard

Perception

Did SAM identify the correct surface before editing?

Precision

How much irrelevant code did it inspect?

Incrementality

Did it reuse prior evidence instead of repeating work?

Planning

Did it find a minimal valid path?

Execution

Did it choose the correct lane and tools?

Recovery

Did it narrow failure before changing code?

Verification

Did it prove the resulting state?

Scope control

Did actual changes match intended blast radius?

Cost

Tool calls, model calls, tokens, embeddings, and wall time.

Friction

How much SAM-specific vocabulary did the operator need?

Product test: a technically powerful primitive that still requires users to memorize twelve commands has not finished becoming a product.

What good looks like

The long-term interface should not force ordinary users to think in Merkle, AST, A*, GOAP, or retrieval modes.
