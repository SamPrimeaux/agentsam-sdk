0 · How the SKU system works

Every reusable piece of the Clay layouts gets one SKU. Edit any SKU in place, or use the bar above to set a prefix and regenerate. Export when you are ready to build.

Format

{PREFIX}-{LAYER}-{CODE}-{SUFFIX}

PartMeaning
PREFIXYour brand or project code, 2–6 characters (default IA). Change it once above; every non-edited SKU follows.
LAYERTKN token · MED media layout · CMP component · SEC section · PG page template · GLB 3D object
CODEShort name for the structure (HERO, CHAP, FULL…). Fixed by the registry.
SUFFIXSequential (01, 02) for readable lists, or random 4 characters (no 0/O/1/I) if you want unguessable, collision-proof IDs.

Normalization rules

  • One SKU per DOM structure. Create a new SKU only when the element tree changes.
  • Variants are parameters, not SKUs: theme (light, tint, dark, brand), side (left/right mirror), slide count, tile aspect.
  • Sections compose components and media. A chapter is one section SKU plus one media SKU, never a new SKU per layout combination.
  • Pages are ordered stacks of section SKUs. A new case study is a list, not new markup.
  • Edited SKUs are locked. Randomize and prefix changes skip anything you typed yourself. Duplicates turn red.
Source tags on every spec: measured I measured it on the live page · your notes taken from the audit text you pasted, not re-measured by me · inferred read from screenshots or derived from other numbers. Measurements are at 1280px (older case studies) or 1440px (Marqeta and Services). Heights scale with viewport width; widths are given as % of viewport.

1 · Tokens (TKN)

The values everything else reads from. Define these once as variables in your build.

2 · Media layouts (MED)

Each layout is defined by horizontal position, width and aspect ratio. Heights follow from those. Diagrams are to scale in width.

3 · Components (CMP)

Atoms and molecules. Sections are built from these.

4 · Sections (SEC)

Full-width page blocks. Each lists the components and media it composes, the themes it accepts, and its content slots.

5 · Page templates (PG)

Observed stacks, to scale (1 block pixel = 50 page pixels). Open one to see its ordered SKU list.

6 · Services page, in detail

Measured at 1440px. Scale drawing (about 0.32×) and the per-row map. The 3D (GLB) objects are registry items too.

7 · Typed schema (TypeScript)

A SKU names a reusable definition. A page is an ordered list of section instances, each with its own id, typed settings, blocks, asset-backed media and a cms_themes reference. Shapes mirror the SDK intake CLI output (page-proposal.json). Nothing here is published by compiling.
