# Hooks, model inventory, and self-hosting plan

Status: active implementation plan (2026-10-02)

## Decisions

### Hooks are one runtime concept

AgentSam has one lifecycle event catalog, one output merge algorithm, and one
receipt format. It has multiple **authoring sources**, not multiple kinds of
hook:

| Source | Authored in | Dashboard/CLI behavior | Durable definition row |
|---|---|---|---|
| `code` | SDK registration | visible, read-only | no |
| `config` | `agentsam.hooks.json` or `.agentsam/hooks.json` | visible, file-owned | no |
| `stored` | CLI/API/dashboard | visible and mutable | `agentsam_hook` |
| `system` | AgentSam runtime | visible, read-only | only when a host intentionally materializes it |

React hooks (`useAgentHooks`, `useHookList`) are UI implementation details and
must never be called lifecycle hooks in product copy.

Dispatch order is priority, then hook key. Source does not create a second
semantics path. A source badge answers where to edit a definition. Execution
receipts from all sources go to the same `agentsam_hook_execution` projection.

### Portable ownership is owner + optional scope

The portable hook schema deliberately has no `tenant_id`, `workspace_id`,
`user_id`, `person_uuid`, or installation-specific foreign keys.

- `owner_id` is an opaque host/account/local owner key.
- `scope_type` is `global`, `account`, `repository`, `project`, or `session`.
- `scope_ref` contains the corresponding opaque id/path when needed.
- `agent_run_id`, `session_id`, and `conversation_id` are the common execution
  correlations.
- Rare correlations (plan, todo, workflow run, command run, route) belong in
  `correlation_json`, not a permanently sparse column set.
- `workflow_id` is a soft reference on the definition. The hook pack remains
  installable without a workflow table family.
- Handler credentials are references resolved by the host. They are never
  values in `handler_config_json`.

The canonical fresh-install SQL is
`migrations/runtime/0005_agentsam_hooks.sql`. The standalone hooks package
ships a generated byte-identical copy plus `schema/manifest.json`.

Existing hosted tables with required `user_id` or tenant/workspace columns are
**not** silently rebuilt. The hosted owner must inspect references and run an
explicit copy/verify/swap migration. Portable initialization is idempotent and
will not guess that `user_id` equals an account owner.

### The existing model surfaces keep their jobs

No new per-model-per-user table is introduced.

| Existing surface | Authority |
|---|---|
| `src/models/catalog.js` / hosted `agentsam_model_catalog` | curated provider-qualified reference capabilities; never credential availability |
| `agentsam_model_pricing` | global/versioned reference pricing |
| `agentsam_plugins` with `plugin_kind='ai'` | one installation per account/environment/provider/credential reference; health and last good credential-scoped model snapshot |
| `user_secrets` / machine vault | provider secret material; never model metadata |
| `agentsam_api_credentials` | authentication to AgentSam itself; never provider keys |
| `agentsam_model_eval_observations` | eval evidence; not a portable customer model catalog |

A successful provider probe writes a compact
`agentsam.provider-model-snapshot.v1` object into the AI plugin row's
`metadata_json.model_snapshot`. It contains sorted model ids, count, hash, and
fetch time. `recordAiPluginModelDiscovery` writes it through the existing
plugin registry and health-check log. A failed probe updates health evidence
but preserves the last good snapshot. Secret values and hashes of secret values
are never included.

The provider API remains the availability authority at use time. A snapshot is
stale-while-revalidate evidence for UI convenience, not an authorization gate.
Reference catalog enrichment is never an availability claim. Unknown models
continue to work with unknown/reference capabilities where the adapter can use
them.

Provider/model identity is the pair `(provider, provider_model_id)`. The SDK's
`model_key` already encodes that pair (`openai:gpt-…`, `cursor:…`). Hosted SQL
must use `UNIQUE(provider, model_key)` (or a provider-qualified `model_key`),
not global `UNIQUE(model_key)`. Provider ids should match SDK canonical ids:
`openai`, `anthropic`, `gemini`, `xai`, `cursor`, `cloudflare`, and `ollama`.
Display names are not ids.

## Product and CLI experience

`agentsam hooks` and `/hooks` are the factual control surface:

- `status` — source counts, project config, and stored registry health.
- `list` — merged dispatch order with source, handler, state, and priority.
- `executions` — recent value-free receipts and redacted failures.
- `validate` — portable config validation.
- `init` — idempotently creates `.agentsam/hooks.json`.
- `enable` / `disable` — toggles stored definitions only.

The dashboard should consume the same status/list/execution projection. It must
not maintain a second event list or merge algorithm. Code rows are read-only;
config rows link to their source file; stored rows expose full editing. A future
priority/disable override for code hooks must be an explicit overlay keyed by
`(owner_id, source_kind, hook_key)`, not a copied code definition.

The model picker follows a similar provenance rule:

1. show models discovered for the selected plugin/credential installation;
2. enrich from the global catalog when a provider-qualified match exists;
3. label every limit/capability as provider, reference, or unknown;
4. keep pinned/default visibility in the AI plugin's `config_json`;
5. never write discovered ids into the global catalog.

## Dogfooding matrix

| Runtime point | Hook event | Current owner |
|---|---|---|
| interactive shell open/close | `session_start`, `session_end` | CLI shell |
| submitted/transformed input | `user_prompt_submitted`, `user_prompt_transformed` | provider-neutral runner |
| paid inference boundaries | `pre_model_use`, `post_model_use` | provider adapter |
| capability side effects | `pre_tool_use`, `post_tool_use`, `post_tool_use_failure` | capability adapter |
| provider/tool failures | `error_occurred` | provider/capability adapters |
| autonomous continuation | `agent_stop` | runner with bounded continuation count |
| delegated work | `subagent_start`, `subagent_stop` | delegated-agent adapter |

The interactive CLI loads code, project config, and active stored hooks into the
same runtime. `session_start.modified_config` may override the session's model,
reasoning, service tier, and compaction preference; arbitrary process or path
configuration is not applied. Session context is injected through normal
context items. Every invocation uses the same receipt observer and local
execution table.

`session_end` remains best effort. Handlers must be idempotent, and durable
cleanup must eventually be backed by an idle-session sweeper rather than an
assumption that a process always exits normally.

## Delivery sequence

### Phase 1 — portable core (implemented in this change)

- Canonical portable hook tables and schema-pack manifest.
- Generic injected-SQL hook store for SQLite/D1-shaped adapters.
- Stored/config/code source merging.
- CLI `/hooks` discovery and value-free execution history.
- Actual shell/runner dogfooding, including session and transformed-prompt
  events.
- Compact AI plugin model snapshot contract and existing-plugin persistence API with last-good preservation.

### Phase 2 — hosted compatibility migration

1. Inventory every FK/view/query referencing hosted `agentsam_hook` and
   `agentsam_hook_execution`.
2. Create `_v2` tables from the portable columns plus host-required indexes.
3. Map `owner_id` from the hosted account authority; do not infer it from a
   tenant/workspace label.
4. Move legacy handler fields into `handler_config_json` and legacy correlation
   fields into `correlation_json`.
5. Validate row counts, active definitions, orphan references, JSON validity,
   and sampled execution history.
6. Swap in one transaction where supported; retain a rollback table until
   production verification completes.
7. Add the dashboard API only after ownership checks are enforced by the host.

### Phase 3 — shared dashboard projection

- Expose merged definitions and receipts through an injected HookRegistry API.
- Add source badges, event filters, dry-run input, and last-failure state.
- Add stored-hook create/edit with handler-specific forms.
- Add explicit code-hook overrides without copying handler definitions.
- Reuse the protocol conformance fixtures in UI/API integration tests.

### Phase 4 — model snapshot persistence

- Apply `createAiPluginProbePatch` in the hosted provider probe transaction.
- Compare `models_hash`; avoid writes when the snapshot is unchanged.
- Refresh stale snapshots in the background and through `agentsam models
  --refresh` without blocking startup.
- Keep last good ids on auth/network failures and expose health separately.
- Add retention only to probe history, not the last good plugin snapshot.

### Phase 5 — lifecycle reliability

- Add stale-session sweep and idempotent cleanup jobs.
- Add execution retention/compaction policy.
- Add local↔remote receipt sync by immutable execution id where explicitly
  enabled; never sync secrets or full prompt/tool values.
- Run JSON conformance fixtures in JavaScript, Python, Go, and Rust CI.

## Acceptance checks

- Fresh SQLite and D1-shaped installs produce the same hook tables.
- No portable hook query requires tenant/workspace/user tables.
- A prompt value or tool result value cannot be found in a hook receipt row.
- Config and stored hooks execute in one deterministic priority order.
- The CLI lists every active source that can affect a turn.
- A provider probe with 1,000 model ids produces one AI plugin metadata update,
  not 1,000 catalog rows.
- Failed model refreshes preserve the last successful model id list.
- A catalog miss never blocks a provider-verified model solely because the
  reference package is older.
- Provider and AgentSam credentials remain separate authorities.
