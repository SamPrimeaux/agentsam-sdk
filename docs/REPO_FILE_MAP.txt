AGENTSAM SDK - REPOSITORY FILE MAP
=================================
ASCII orientation map; logical map, not exhaustive per-file inventory.
Scope: tracked layout. Generated, ignored, and machine-local content is omitted.
Baseline evidence: repository audit on feat/public-package-graduation.
Use git status / agentsam context for the current revision rather than treating
this orientation map as revision authority.

1. SYSTEM WIREFRAME
-------------------

  Consumer / developer
       |
       +--> README.md, DEVELOPMENT.md, docs/ -------- architecture, contracts, guidance
       +--> bin/agentsam ------------------------------ CLI launcher
       |      +--> src/cli + src/commands ----------- CLI composition
       |      +--> src/index.* ----------------------- SDK public facade
       |      +--> src/sam --------------------------- typed execution spine
       |      `--> src/* ----------------------------- SDK domains and adapters
       +--> package.json / package-lock.json --------- root npm product and lockfile
              +--> packages/* ------------------------ reusable packages
              +--> apps/* ---------------------------- product applications
              `--> services/* ------------------------ service implementations

  Shared vocabulary: protocol/* + contracts/* + packages/agentsam-contracts
  Data schemas:      migrations/{runtime,sqlite,d1}
  Provider seams:    src/providers, src/cloudflare, packages/connectors/*
  Verification:      test/*, package-local tests, scripts/verify-* and npm gates

3. AUDIT / NAVIGATION NOTES
---------------------------

  * docs/SOURCE_ARCHITECTURE.md defines root src as the SDK/package composition
    layer and calls src/lib a legacy extraction zone. Put new reusable modules in
    a coherent owned package instead of adding unrelated code to src/lib.
  * package.json explicitly enumerates root npm workspaces. Not every directory
    under packages/ is necessarily a configured workspace: check before using
    workspace commands or assuming it is published.
  * protocol/, packages/agentsam-contracts, and root contracts/ are distinct
    locations. Follow their local ownership docs instead of conflating them.
  * Select the correct migration family and owning app/service before changing data
    schemas. App-specific seeds and bindings belong with the consuming app.
  * APP identity/validation: docs/architecture/AGENTSAM_APPLICATION_CONTRACT.md;
    root gates are npm run app:validate / npm run guard:apps.
  * Local filesystem discovery also surfaced folders such as generated/, .wrangler/,
    level-1/, test2/, and agentsam-originalsetup-inspect/. They are omitted here:
    this map describes tracked repository roots, not every local/ignored directory.
  * Public package distribution is audited by agentsam package audit/status/verify/
    publish-plan. A publishConfig alone is intent, not proof that a package is
    consumer-ready.
  * native/agentsam-machine is the Rust machine-perception workspace. Its CLI resolves
    from PATH, a built repo binary, or a Cargo fallback; treat native distribution as
    its own release lane rather than assuming the npm package publishes a native binary.
  * This file is an orientation map, not implementation or release authority.

4. QUICK TEST / RELEASE ENTRY POINTS
------------------------------------

  npm run test:standard       focused root test bundle
  npm run test:workspaces     selected package tests/typechecks
  npm run verify              broad SDK/package/app/boundary/package checks
  npm run verify:release      verify + knowledge package + Python + release security
  npm run app:validate        validate all product app manifests
  agentsam package audit --public
                            compare public intent with registry/quality state
  agentsam package verify <name>
                            run declared package gates + npm pack dry-run
  agentsam package publish-plan
                            dependency-ordered, read-only publication plan

Use DEVELOPMENT.md and each package/app README for current, more detailed commands.
